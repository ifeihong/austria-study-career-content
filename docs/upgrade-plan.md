# 设计模板与内容生产升级方案

本文件保留三模板阶段的升级记录。当前八方向、八模板规范见[八方向八模板方案](eight-system-plan.md)。

本次升级依据：近期三套获认可的设计与后续精排反馈，以及仓库现有五个风格方向。重点解决内容未充分上版、模板不易复用、局部排版不舒服与工具验收不足。保留生活文化、护理职业、家庭规划三条内容主线。

## 1. 将方向、模板、组件、媒介分开

| 层级 | 负责什么 | 本次落实 |
|---|---|---|
| S1—S5 内容组织方向 | 读者怎样理解信息 | 清单、情境、观察、证据、路线；补充各自的页面策略与禁忌 |
| T1—T3 精选模板 | 整套画面怎样保持精致与一致 | 三套可运行 JSON、实际配图、统一字体系与布局 CSS |
| 页面组件 | 一页如何呈现任务 | 图片封面、侧图解释、卡片、条带、指标面板、服务分组、步骤网格、工作表 |
| 配图媒介 | 用什么画面完成任务 | 照片感、插画、漫画、授权实拍、图解、原始资料；按内容选择 |

这是可组合的设计体系，不宣称有15套已独立验证的模板。模板来源以用户最后确认的护理陪伴版、7页完整重设计、护理精排版为准。

## 2. 三套模板如何升级

| 模板 | 保留的优点 | 深化方式 | 使用限制 |
|---|---|---|---|
| T1 温暖陪伴叙事 | 暖米白与深绿、场景照片、陪伴式阅读 | 叙事封面、双图文解释、路线与分组、自然交流 | 不把温暖叙事变成虚构客户故事或未经确认的服务保证 |
| T2 雾蓝完整编辑 | 清晰、稳定、职业教育氛围 | 分区人物封面、冷暖强调、分类条带、成组说明 | 不做成所有页面相同的大卡片；图片不遮挡正文 |
| T3 暖白酒红精排 | 长文舒适、信息完整、层级克制 | 连续段落封面、两列要点、上下指标、均衡步骤 | 不能用增加段距掩盖内容空泛；少字页可合并 |

将原成品抽象为可复用组件，公开示例替换为护理准备方法文案。原项目的具体补助、语言门槛、服务承诺与逐日记录不进入公共模板。模板示例分别9/7/7页，只用于展示组件，后续不固定页数。

## 3. 五个方向如何深化

每个方向补齐：适用读者问题、至少两种结构变化、主要媒介、可收藏的信息产物、自然评论切口、常见失败与模板选择。详见[风格库](../references/xiaohongshu-styles.md)。

S1关注真正能使用的分类、清单和字段；S2通过场景和解释推进；S3用具体观察连接生活与信息；S4保留原始证据及条件；S5讲清比较维度和顺序关系。保持五个方向的稳定名称，不因题材或配色变化不断增加编号。

## 4. 从最近修改中修复的问题

| 实际问题 | 生产规则 | 验证方式 |
|---|---|---|
| 用户要求完整原文，但设计中漏项或压缩 | 先确认原文保留模式；逐项映射上版位置 | 原稿→定稿人工核对，定稿→渲染文字自动比较 |
| 标题像内容、内页缺少实质信息 | 每页明确新增解释、方法、观察或可用字段 | 不能只看页数和字数；读者是否得到具体收获 |
| 四列短栏导致碎读，标题断字 | 控制行长与栏目数量，长条件改宽版 | 手机宽度逐页阅读，检查孤字与术语 |
| 封面图片与引言关系松散 | 建立标题、图像、引言三段关系 | 看人物裁切、图文间距与视觉重心 |
| 服务/流程页靠自动留白撑满 | 按信息组设置间距，而非把结尾顶到底 | 检查相邻信息关系和无作用空白 |
| 多次配图重复、裁切伪装新图 | 逐页独立场景，保留素材清单 | 相同源文件哈希自动拒绝；近似画面人工看 |
| 输出成功被等同于精致完成 | 分开内容、技术、视觉、发布字段四项验收 | 原图、手机预览、整套缩略图分别检查 |
| 最终文件可能沿用旧导出 | HTML、输入、文字审计和图片摘要关联 | 离线包检查发现修改后未重新导出的文件 |
| 品牌昵称有时缺失 | 页脚保留正确署名，不靠图片生成中文 | DOM文字比较与实际成图检查 |
| 图文和文案冒出AI来源字样 | 来源放内部记录，发布标识由团队手动操作 | 清理旧样稿，并保留工具已有强制标识 |

## 5. 完整生产流程

确定范围与保护项 → 查询历史 → 读取可用来源与原稿 → 核验主张/记录缺口 → 确定原文保留模式 → 分配页面任务 → 选择S方向、T模板及逐页媒介 → 制作实际素材 → 组织上版文本并核对原稿 → 导出与技术检查 → 逐页原图及手机预览 → 匹配标题正文标签 → 最终文件完整性检查 → 本地版本登记 → 交付。

纯设计修改不自动改稿或重查全部政策，也不能据此宣称原稿事实已确认。若发现明显的高风险主张，单列需要核实的项目；不得把无依据承诺写成模板默认知识。用户要求只修改图片时，配套文案仅在受影响时调整，不重复强制交付整套运营方案。

## 6. 内容与运营功能补足

- **专业内容**：保持教育、认定、注册、录用、就业许可和居留概念分开；专业事实使用具体来源与读取日期。
- **生活文化**：保留纯欣赏与文化观察，不强制每篇导向业务；用物件、动作、空间和日常选择提供新鲜感。
- **资料有限时的原创**：从公开信息建立独立解释、对照表、问题清单与生活观察；不编造采访、经历或客户案例。
- **收藏与评论**：收藏价值来自可使用的内容，评论来自具体、易回答的问题；不要求读者公开收入、健康或证件信息。
- **SEO/GEO**：标题与正文自然说明地区、对象、问题、结论与条件；图片之外保留可检索文字，不承诺排名、流量或AI引用。
- **跨平台**：沿用同一事实底稿，重新适配节奏与信息量；脚本不冒充成片。公开视频与图文不自动授权对外发布。
- **复用与历史**：同题新解释与单纯视觉改版分开；后者关联原作品，不算新增选题。

## 7. 工具与交付

主渲染器增加template选择、五种页面组件、输入文字逐项比对、场景图完全重复拦截、文本裁切检查及模板代码摘要。独立包检查器检查源文件、图片、发布复制文件一致性。保留原工具兼容路径和本地历史，不添加后台采集或遥测。

README展示真实新模板预览，说明三模板与五方向的关系、选择示例、工具能力和边界。旧生活/护理/家庭样稿仍有用途，但清理过时的可见AI字样并更新展示图。

## 8. 验收与发布标准

先运行非浏览器测试，再运行浏览器回归：旧五类基础输入、旧三套正式样稿、新三套模板、可迁移源、局部改页、重复图片拦截、陈旧文件检测和本地历史。新示例需实际出图和目视检查；无溢出不等于审美通过。

提交前审核公开文件清单，排除本机路径、逐日台账、私有配置、内部服务材料与未经核实的原项目承诺。GitHub提交后核对远端分支提交及README，不能只以本地提交代替同步完成。
