# 小红书图文：从主题到可发布成品

## 目标与交付模式

用户要求“小红书图文”“完整笔记”“可以发布的内容”时，默认制作完整发布包：封面和全部内页的独立图片、标题、发布正文、相关话题、整套预览。只交文案、分镜、提示词或 HTML 源码不算完整发布包。用户明确只要选题、文案或设计提案时，按其范围交付。

“效果”指信息价值、品牌辨识、视觉质量和成品可用性。点击、收藏、咨询与流量是发布后才能观察的结果，不承诺爆款。没有真实数据，不宣称某版已经提高转化。

## 最少输入与合理默认

从对话提取主题、主读者、已有资料、可用图片与本篇目标。明确需求直接执行，不将创作拆成多轮问卷。只有会改变事实或权利的缺口必须补证，其余采用明示的合理默认。

默认中文竖版、同一套统一比例，可先采用 1080×1440 像素作为制作规格；这是本 skill 的工作默认，不是平台上传规则。用户有指定规格就遵循；涉及现行平台限额、裁切和投稿规则时查官方说明或当前上传界面。

没有完整品牌视觉系统时，选一套适合当前主题的临时设计，并说明它是提案。不能默认为品牌新增 Logo、既有人物或官方配色。

## 1. 将主题转为可兑现的内容承诺

明确本篇读者、眼前问题、阅读后可完成的动作、需要的证据。每篇有一个主要承诺。

必要时形成三种真正不同的切口，例如同一预算主题可做分类清单、家庭讨论或决策比较，比较它们的信息价值和证据成本。要求完整成品时自行推荐并完成，不为选择同义标题暂停。

创意来源可以是材料特写、生活动作、对比、账本、时间轴、选择题、标注的假设情境。参考账号只提炼表达机制，不照搬文案、版式与图片。

## 2. 协同设计发布标题与封面

- 发布标题：明确主题与适用读者，自然使用真实相关的搜索表达。
- 封面主标题：在小图状态下仍能读懂问题或收益，不能依赖正文补完含义。
- 辅助信息：给出人群、范围或具体切口，不重复主标题。
- 主画面：支撑内容承诺；可选信息图、实景、材料或物件，不强行每篇放风景或人物。

发布标题与封面可以不同，但不能互相矛盾。不用虚构数字、最后机会、内部消息和身份收益制造刺激。三个标题如被提供，应改变角度而不只是换词。

## 3. 按信息选择结构与页数

| 结构 | 信息重点 | 可采用的推进方式 |
|---|---|---|
| 清单 | 分类和优先级 | 问题、分类、核对、行动 |
| 对比 | 对齐维度与条件 | 选择、差异、例外、判断 |
| 过程 | 顺序与依赖关系 | 起点、步骤、卡点、下一步 |
| 证据解读 | 原文及适用范围 | 问题、原文定位、解释、条件 |
| 情境 | 不同人的真实顾虑 | 标注情境、分歧、拆解、行动 |
| 决策 | 自己如何判断 | 问题、变量、选择、待确认项 |

页数随内容确定，通常先考虑 4—7 页，简单主题可以更短。每页完成一个信息任务，不为了凑页重复，不把行动页机械写成咨询广告。

先写每页的信息任务与可上版文字，再确定图示、图片、留白及来源位置。含数字和条件时要留足阅读空间；信息拥挤优先删减或拆页。

## 4. 设计整套视觉

先读 [风格库与插画、emoji 规范](xiaohongshu-styles.md)。按任务选择主要风格；日常家庭与准备类内容优先考虑匹配的 AI 插画与轻量 emoji，资料密集页可以不用。不把五种风格方向说成已附带五套成品模板。

固定同一套中的画布、字体系、品牌署名、边距、页码和来源样式。封面、解释页和行动页可以采用不同构图，避免所有页都变成相同卡片模板。

制作参考而非硬阈值：1080 宽画布可从封面大字 80—120 px、内页标题 56—76 px、正文 34—44 px 试排，重要注释尽量保持 26—30 px 以上；安全边距先按 64—80 px 考虑。最终以手机尺寸实看与实际内容为准，不通过小字隐藏重要条件。

保持足够对比，减少装饰色和无意义图标。护理与家庭可用不同主题画面，但品牌署名与文字层级要统一。长词、德文、币种和术语不可随意拆断或丢失。

## 5. 完成图片制作

基础清单、步骤、表格和分栏可复用 [制作工具](production-tools.md)；复杂版式按内容另行设计。局部改图遵循 [版本与修改规则](revision-and-private-data.md)，不能无故重做已经确认的内页。

根据内容选路径：

- 原生文字、表格、清单、时间轴和简单图示：可用 HTML/CSS、SVG 或其他可控排版工具渲染，保留可编辑源文件。最终仍需导出独立图片。
- 需要摄影、插画、合成场景：使用当前可用的图像生成工具或有使用权的素材；实际生成/编辑图片时遵循对应工具与 skill。不能用程序拼几何图形替代明确要求的摄影或插画。
- 真实证据：使用可核验且有使用授权的原始资料，脱敏并保留关键上下文；不能 AI 生成合同、批文、工资单来作证。

关键中文、数字、来源和品牌署名优先采用可控文字排版。AI 素材需检查画面语义与文字错误，不能把提示词当作成图。数字人与合成场景的适用标识保留在成品中。

无法生成或导出图片时，明确能力缺口与已完成部分，不能将策划稿叫作可发布成品。

## 6. 配套发布文案与搜索表达

交付一个推荐标题，可另附少量备选。正文直接进入问题，补充条件、使用方法或图中未展开的解释，避免逐页复读。结束可建议填写、保存或讨论，不强制“私信领取”。

确定一个主要问题，围绕人群、地点、事项自然组织标题与正文。实体称谓一致、回答明确、来源可追溯，便于读者与检索系统理解；不固定关键词密度、不堆话题、不承诺 SEO/GEO 效果。

话题只选与本篇真正相关的少量词。需要符合平台现行字数与话题限制时实时核对，不能把历史限制写死在 skill 中。

## 7. 核验与成图检查

事实审核调用 [evidence-review.md](evidence-review.md)。可发布成品中不能残留待核验政策、价格占位符、假链接、未兑现资料承诺或内部设计备注。

实际导出后逐张检查：

1. 图片存在且可解码，尺寸、比例、格式与数量一致，按发布顺序命名。
2. 标题与封面承诺在内页兑现，翻页顺序清楚，没有重复页或漏页。
3. 无溢出、遮挡、裁切、错字、缺字与乱码；关键条件和来源可见。
4. 将图片缩小至约 360—420 像素宽检查手机阅读，再看原尺寸细节。整套缩略图不能替代逐页检查。
5. 若有摄影、AI 或资料截图，检查真实性标识、授权、脱敏与画面语义。
6. 核对标题、正文、图片中的品牌、数字、结论和 CTA 相互一致。
7. 有 AI 插画时检查主题匹配、跨页一致性及示意标识；有 emoji 时检查最终导出中的缺字、基线与清晰度。图片和表情不能挤占重要条件与正文。

发现问题就修改并重新导出相关页。机械检测只能辅助；只有格式检查时不能声称已经完成视觉审核。没有在真实设备或平台投稿页检查时，不得宣称已做真机或上传验证。

## 8. 发布包与可编辑交付

建议交付结构：

```text
主题-slug/
  images/
    01-cover.png
    02-主题.png
    ...
  publish.md
  preview.jpg
  source/
```

`publish.md` 将推荐标题、正文、话题分开，便于复制。`images/` 只放用于上传的独立图片。`preview.jpg` 是整套预览，不能代替单张成品。`source/` 保留可编辑排版和必要素材；内部核验记录与制作备注放其中或单独文件，不混进发布正文。

最终给出封面预览、整套预览与发布包链接，并说明尚未确认的限制。可发布只表示成品已制作和检查，不表示已上传。用户未授权时不登录、发布或回复评论。

## 验证本模块的实际能力

至少用一篇完整样稿检验从主题到导出。后续增加不同结构时，优先用护理线、家庭线和证据解读型的真实任务验证。检查是否真正提供独立图片与发布文案，是否在缺少证据时改写内容，是否能在手机尺寸阅读。

不能把固定措辞、某个配色或相同页数当作测试通过标准。已有样稿只证明对应内容与排版路径，不自动证明图像生成、联网核验和平台上传能力。
