# 从发布反馈改进下一篇内容

用户提供发布数据后读取本页；日常创作若无反馈，不虚构指标或强制展开运营报告。原始数据与身份对应按[本地反馈结构](publishing-feedback-schema.md)保存，评论和咨询资料不进入公共仓库。

## 先确定比较条件

核对平台、体裁、实际发布时间、统计截点、观察年龄、投放状态和最终采用版本。缺少任何项就标明，不用文件mtime代替统计时间，不把较早作品的累计量当作新作品的效率基准。

建议在实际可取得时保存发布后约24小时、72小时和7天快照；常青知识可增加30天观察。错过窗口记真实时间，不补造快照。本Skill不因此创建定时任务，也不规定每周发文数量。

同平台、同体裁、同主要任务、相近观察年龄及相同投放条件下比较。顺序发布的不同文章不称为严格随机A/B；题材、封面、画风和时间同时改变时，只描述结果与待验证解释。

## 每篇选择一个主要任务

| 主要任务 | 内容例子 | 优先观察 | 不作替代 |
|---|---|---|---|
| 引起兴趣 | 季节、城市日常、文化现象 | 匹配窗口的曝光、平台点击率、可得的开头留存 | 曝光不等于客户需求 |
| 提供保存价值 | 操作、词汇、对照、步骤 | 收藏次数及收藏/观看次数比 | 收藏不等于实际使用人数 |
| 建立持续关注 | 文化故事、连续专题、清楚的专业解释 | 表内涨粉字段、后续主题提问 | 作品涨粉合计不是账号净增粉 |
| 解释具体准备问题 | 学习、职业、家庭生活专题 | 真实读者问题、实际提供的主动咨询 | 评论数不是咨询人数或资格判断 |

可以有一个次要任务，不要求每篇同时追求最高曝光、收藏、评论和咨询。美好生活可以止于欣赏与交流；专业内容可以服务较小、较具体的受众。

## 指标解释

- 封面点击率按平台原字段保留；观看量÷曝光与该字段不符时不自行覆盖。缺定义时保持原口径，等待官方说明或当前后台解释。
- 收藏次数÷观看量等次数比应显示公式；分子、分母来自相同数据范围和窗口。组内比率使用总分子÷总分母，不简单平均百分比。
- 人均观看时长要核对单位；即使有视频总长，二者相除只是平均观看占比，不能替代真实完播率。图文停留与视频时长也不直接混排。
- 缺失、0、不适用、尚未统计分别处理。没有投放信息不默认自然流量，没有独立观看人数不称用户转化率。
- 少量观看下的高比例易受个别行为影响，必须同时呈现绝对数量。不给所有账号套用CTR门槛、万能最佳时间或“爆款概率”。
- 同一笔记后续快照是累计数，不能直接相加。若手工比较净变化，先确认noteId、口径与时间先后；计数下降可能是撤回或修订，不截成0，不当作新互动。
- 制作工具、媒介、模板、题材分别记录。没有作品版本与工具来源映射，不比较“某工具更会涨粉”或“某画风带来咨询”。

## 读到什么，下一次改什么

| 观察 | 先检查 | 可测试的下一步 |
|---|---|---|
| 曝光少且样本极小 | 年龄、投放、来源、统计完整性 | 标为数据不足，不急着删除题材或重做全套 |
| 有一定曝光，同类点击偏低 | 地点/事项能否一眼看清、主图是否直接对题 | 下一篇优先调整封面承诺，尽量保持主要任务 |
| 点开后保存少 | 答案是否太晚、是否只有泛泛标题 | 更早给具体解释、对照、步骤或实例 |
| 保存尚可，持续关注弱 | 账号后续提供什么是否清楚 | 做有独立增量的专题与主页索引，不机械加关注口号 |
| 阅读后少有讨论 | 问题是否过泛、是否必须亲历才能答 | 换成一个具体偏好、困难、经验或好奇问题 |
| 反复问同一专业问题 | 原文是否遗漏或歧义 | 先补清楚答案，再判断是否值得独立成文 |

每次复盘输出：**观察事实 → 可能解释 → 待验证假设 → 下一篇主要改动 → 保持项 → 还缺什么数据**。有重复证据且用户认可后再调整默认偏好，不因一篇好或差就改写品牌规则。

## 评论与主动咨询

原始评论脱敏后区分生活偏好、实操困难、专业问题、主动咨询、纠错。另记录是否为作者回复；统计10条评论不意味着10个独立读者。

回复草稿先回答可公开讲清的部分，必要条件同时给出，不故意省略关键信息诱导私信。普通偏好交流不强行转销售；不从留言推断收入、资格、获批或付费意愿。

实际咨询归因仅在团队确有记录且用途明确时分析。缺私信、预约和服务数据就写缺失，不把收藏、关注或评论折算成客户数；不主动联络读者。
