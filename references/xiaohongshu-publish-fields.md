# 小红书普通图文：发布字段与图文对应

## 适用范围和核验记录

适用普通图片笔记的发布标题、正文及话题，不把长文、特殊入口或某个账户的扩展能力套用到普通图文。

来源：[小红书电商学习中心 · 笔记创作课程](https://school.xiaohongshu.com/lesson/normal/af0fe7e97bb0433fac9da5d1df52b07f)。使用时优先核对当前官方说明或实际投稿界面的计数器。不要为了“最新”只改日期。

## 每套必交的字段

| 字段 | 制作要求 | 本地保守检查 |
|---|---|---|
| 发布标题 | 一个推荐标题，准确概括这套图文；封面文字可更长，但不直接拿来充当超长发布标题 | 单行，不超过 20 个 UTF-16 代码单元，包含标点、空格及 emoji |
| 发布正文 | 自然开场、必要解释/使用方法、与图片一致的条件、自然交流问题（如适合）及必要出处 | 正文与最终话题串连同分隔换行合计不超过 1000 个 UTF-16 代码单元 |
| 话题/tag | 通常选 4—6 个真正相关的候选词；题材窄时可以更少，最多 8 个为本地编辑上限 | 单个名称无空格、标点或 emoji；可由中外文字母、数字和下划线组成；去重，不堆泛热词 |

20/1000 来自上述官方课程参考；UTF-16 计数是本工具的保守算法，不是宣称小红书同样计数。常见 emoji 可能占两个或更多单元，空格、换行、标签文本一并预留，远离边界更稳妥。官方课程中的“话题建议 4—8 个”不是硬上限：不把网上流传的 10 个写成已核实规则，也不要求每篇凑满话题。

创作时按内容自然使用少量 emoji，例如开场情绪、分组及交流处；本品牌的完整图文默认提供含 emoji 的正文，用户要求纯文字或素材解读需克制时相应调整。emoji 不替代关键术语，不用于制造夸张收益或挤占条件。发布标题不强制带 emoji。

## 先配图文，再验字段

每套单独完成，不生成一份可套给所有图片的通用介绍：

1. 对照实际图片，内部记录“封面承诺 / 每页新增信息 / 正文对应解释 / 话题依据”。不能只看选题名就写配套文案。
2. 发布标题可与封面不同，但人群、主题、数字与收益一致；图中没有的清单、价格或结论不能写进标题。
3. 正文用自然段解释整套内容和使用方式，适度补充，不逐页抄一遍，不写“如图可见”却无法在图片找到对应内容。无证据的新事实不靠文案临时添加。
4. AI 场景不写成“今天实拍”“我住的地方”或客户见证。公开出处用简洁机构/条目名称；完整链接、读取范围和核验记录保存在项目来源文件，不把制作备注混进正文。
5. 话题覆盖真实地点/主题、内容事项与读者需求，不附不相关职业、城市或身份营销词。不声称候选标签已存在、有特定热度或能保证曝光。
6. 先改内容再改图片时，同步检查另一边。超长时主动重写精简，不静默截断，不删除限制条件来凑字数。

## 素材记录与手动声明

封面、内页、图注和可复制的标题、正文、话题不自动添加「AI 示意」「AI 生成」或同义来源提示。生成图片时也不要求把这些字写进画面。使用渲染器时，不用 `imageLabel`、`note` 或 `publish.body` 添加这类提示。

有生成或合成内容时，将使用位置（配图页码或对应字段）、素材性质和来源记录放入独立的内部核验文件，并提醒团队在发布时手动使用平台声明功能。按实际投稿界面的要求操作，不把内部提醒复制进正文。保留素材已有的必要标识和来源元数据。若导出方式无法保留所需标识，改用能保留标识的方式或更换素材。依据见[《人工智能生成合成内容标识办法》第十条](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)。

## 输出文件与复制方式

渲染输入中的 `publish.title`、`publish.body`、`publish.topics` 与每套图片一一对应。topics 填名称，前导 `#` 会规范化；不要把标签同时写入 body，避免重复。

- `publish.md`：标题、正文和话题分区，便于整体审阅。
- `publish-title.txt`：只含发布标题，可复制到标题栏。
- `publish-body.txt`：正文 + 一次话题串，可复制到正文栏。
- `publish-topics.txt`：单独的话题串，供需要分开操作的界面使用；已复制完整正文时不再次追加。
- `publish-check.json`：内部计数、参考配置和未实测投稿页状态，不复制到平台正文。

普通投稿界面的话题通常需要从输入建议中确认，复制 `#名称` 不代表已成功挂接话题。本 Skill 提供候选词，最终以当前界面的识别、计数、标签可用性及 AI 声明入口为准；没有实际操作时不声称已经完成平台字段校验或发布。

工具检查只验证保守长度及格式，不能判断文案和图片含义是否相符，也不能保证平台接受、审核通过或流量。当前配置需要更新时，先核对证据，再同步制作规范、脚本与边界测试。
