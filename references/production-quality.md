# 内容、精排与交付质量检查

## 内容先过关

知识页给出具体分类、解释、例子、字段或操作；不要只把标题拆成数页。生活页可以以画面与观察为主要价值，但要有真实可读的细节。每页写清“读者新增知道什么/看见什么”；相邻页只有换词重复时合并或重组。

专业内容先核对对象、时间与条件，不通过藏限制提高吸引力。服务范围以已确认能力为准，不把资料整理模板自动变成“全程保障”。公众知识、内部业务背景与具体客户判断分开。

## 逐页精排

| 检查项 | 不舒服的表现 | 优先修正 |
|---|---|---|
| 主次 | 标题、副标题、正文同时很粗很大 | 减少层级，突出一个阅读入口 |
| 断行 | 单字落行、括号分离、缩写与单位拆散 | 调整语义换行、栏宽或组件，不用极小字 |
| 行长 | 四窄栏放长句，读一条要折返多次 | 改双列要点、全宽条带或拆页 |
| 字间距 | 两端对齐拉出大空隙，负字距挤成一团 | 正文左对齐，恢复自然字距 |
| 组内关系 | 标题离正文过远，正文贴边 | 统一组内间距和内边距 |
| 图文关系 | 标题贴照片、图像与说明脱节 | 对齐图文边界，设置独立呼吸区 |
| 视觉重心 | 上方拥挤，底下大片无作用空白 | 改信息分组、图像比例或合并页 |
| 条件 | 金额醒目，适用条件缩成脚注 | 将金额和条件放同一阅读组 |
| 装饰 | 边框、圆角、线条样式越来越多 | 每套保持有限、一致的装饰语汇 |
| 品牌 | 昵称遗漏、错字或压住图片 | 用可控文字页脚，核对“桔”字 |

规则以实际文字和画面为准；不是每页加满字，也不是一律压缩留白。多次反馈同一问题时，回到组件结构解决，不继续只改底色、阴影和字号。

## 四项验收分别记录

1. **内容**：原稿保护模式、信息增量、主张与条件、图文正文一致性。润色完整性由原稿对照证明，不能仅报段数。
2. **技术**：文字输入实际渲染一致、裁切、图片解码、重复源图、输出尺寸、源文件及图片摘要。自动工具有明确边界。
3. **视觉**：逐页原图、360—420像素宽预览和整套缩略图。检查细节、阅读与节奏三种尺度；整套小图不代替逐页。
4. **发布字段**：实际配图对应的标题、正文和话题，复制文件一致，字段本地预算通过，实际投稿界面另核。只做排版修改时不强制扩写正文。

## 防止旧图混入新交付

内置渲染器在manifest中记录源HTML、输入JSON、渲染文字核对及每张图片摘要。使用：

```sh
node scripts/audit-package.cjs output/new-version
```

工具发现修改后未重新导出、图片错配、额外PNG或发布复制文字变化时拒绝通过。它检查本地包一致性，不证明原稿语义完整、政策正确、设计漂亮或已发布。自定义HTML/CSS也应采用同样的最终源文件/图片摘要关联，实际导出失败时不继续打包旧图。

## 从反馈到下一次制作

在用户项目记录：版本、具体不满意页面、问题类型、修改方式、保留项、检查结果。仅当前主题的特殊需求不固化成全账号硬规则；反复出现的排版和完整性问题才更新模板/规范。没有后台数据时只能说设计反馈，不能推断收藏或咨询增长。

每次实际成品按本地历史规则登记。样稿测试使用临时目录且不写真实台账；公开模板、实际客户内容和本机安装配置分开维护。


## 每页页尾署名

封面、全部内页和末页页尾保留“奥地利求学就业桔”，保留“桔”字。署名与页码对齐并留距离，避免贴边、压图或过小。内置渲染器逐页检查品牌文字、页尾安全位置和至少22px字号，manifest记录brandFooter结果；这是技术下限，实际以手机阅读检查为准。外部工具和自定义版式同样执行。
